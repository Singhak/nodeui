NodeUI Architecture

NodeUI aapke Node app ke andar hi chalne wala local developer console hai. Yeh page batata hai ki data kahan se aata hai, kahan jaata hai, aur har feature code mein kahan rehta hai.

Poori tasveer

Sab kuch aapke app ke process ke andar chalta hai. Koi alag server, database ya cloud nahi. Bahar sirf browser, CLI aur aapke chune hue opt-in sinks jaate hain.

Ek hi process

Console aapke app ke process mein hi mount hota hai. Alag port, container ya cloud nahi lagta.

Do raaste andar aane ke

Adapter se (app.use(middleware)) ya CLI se (nodeui attach -- node server.js, code badle bina).

Core framework-neutral

Express, Fastify, Nest sab sirf patla wrapper hain. Poora kaam @singhak/nodeui-core karta hai.

UI core ke andar bundled

React app ka build packages/core/static mein jaata hai, isliye UI aur API ka version kabhi mismatch nahi hota.

Ek request ka safar

Adapter ka middleware har request pehle dekhta hai. Wahin tay hota hai ki yeh aapke app ki request hai ya console ki.

  • Request aati hai, id milti haireserveId() ek requestId deta hai aur bindRequestId use req se jodta hai. runWithRequestId baaki poori async chain ko wahi id deta hai.
  • Handler chalta haiHandler ke andar jo bhi outgoing call, SQL query ya console.log hota hai, wo wahi requestId uthata hai (AsyncLocalStorage).
  • Response khatam hone par recordres.on('finish') par duration, status aur bytes nikalkar timeSeries, routeMetrics, requestsProvider aur metricsProvider mein jaate hain. Beech mein client ruk gaya (close) to wo requestAborted ginta hai.

Data kaise pakadta hai

NodeUI aapke code mein trackRequest() jaisi calls nahi lagwata. Woh Node ke built-in jagahon par hook lagata hai.

capture: 'always' (default)

Hooks startup se lagte hain. Problem ke baad console kholo to pehle ka data mil jaata hai.

capture: 'lazy'

Hooks tabhi lagte hain jab koi panel khula ho, aur inactivityTimeoutMs (60s) ke baad hat jaate hain. Console band ho to zero cost.

Dusre tools ke saath

OpenTelemetry, Sentry ya APM ne upar wrap kiya ho to NodeUI unka wrapper todta nahi. Wrapper apni jagah par ho to hi hatata hai, warna passthrough ban jaata hai.

UI aur live data

UI ek React single-page app hai. Woh jis URL se serve hui hai usi se <prefix>/api nikal leti hai, isliye kisi bhi path prefix par chalti hai.

Ek stream, kai panel

live.ts ek hi EventSource rakhta hai aur subscribe hue panel ids ka union maangta hai. Naya panel khule to stream ek baar dobara khulti hai. Disconnect par backoff, max 30s.

Server ki taraf se limit

Ek saath khuli streams ki limit maxSseClients hai. Zyada hone par 429 too-many-streams milta hai.

Routing

Hash router (router.ts). Filters URL mein rehte hain, to link share karne par wahi view khulta hai.

Views

Overview, Metrics, Load tests, Profiler, Alerts, Endpoints, Requests, Outgoing, Queries, Errors, Logs, Env, Routes, Runtime, aur aapke plugin panels (GenericView).

Metrics, load tests, alerts

Yeh "local Grafana" wala hissa hai. Har request ke finish par ek hi time-series engine bharta hai, aur uske upar alerts, diagnose, load tests aur CI check baithte hain.

Safety: console kab aur kise dikhta hai

NodeUI app ke andar chalta hai, isliye default sab kuch band rakhta hai. Guard ke checks isi order mein chalte hain.

  1. Activation (startup par ek baar)NODEUI_ENABLED=true/false sabse upar. Warna NODE_ENV!=='production' ho tabhi ON. Production mein bina override ke band (fail-closed).
  2. Remote addressLoopback mode mein sirf 127.x, ::1 allowed. Docker ke liye allowedRemoteAddresses (IP ya IPv4 CIDR).
  3. Proxy headersX-Forwarded-*, Forwarded, X-Real-IP mile to reject, jab tak trustProxy na ho.
  4. Host headerLoopback naam hi chalega (DNS-rebinding se bachav). Dusra naam allowedHosts mein dalna padta hai.
  5. Origin headerCross-site call reject, jab tak Origin usi Host ka na ho ya allowedOrigins mein na ho.
  6. Token (optional)Bearer, x-nodeui-token, cookie ya ?token=. Compare timing-safe hota hai. Query token mile to cookie set hokar redirect ho jaata hai.

Badalne wale kaam par nonce

Heap snapshot, profilers jaise POST kaam ke liye pehle /confirmations se single-use nonce lena padta hai (TTL 60s). Header: x-nodeui-confirm.

Secrets masked

maskSecrets har panel output par chalta hai: tokens, keys, passwords, DATABASE_URL jaise names [REDACTED] ho jaate hain. Request headers mein credentials hamesha redacted.

Replay ka target fixed

Replay sirf app ke apne socket address par jaata hai, jo real request se seekha gaya. User sirf path de sakta hai.

Host app ko kabhi nahi todta

Samplers aur driver patches try/catch ke andar hain. Fail hone par console band, app chalta rehta hai.

Packages (monorepo)

npm workspaces: apps/* aur packages/*. Adapters patle hain, asli kaam core mein hai.

PackageKaam
packages/coreEngine: server, guard, providers, registry, safety, SSE, static UI. UI ka build static/ mein yahin rehta hai.
packages/expressnodeui() → { middleware, server, addLogSource, errorHandler }. Core ko re-export karta hai.
packages/fastify, koa, hapi, hono, httpApne framework ka plugin ya middleware, wahi core ke upar.
packages/nestjsDynamic module + service + interceptor + logger (nodeui.module.ts, nodeui.interceptor.ts).
packages/cliattach (preload), dashboard, mcp, check, digest.
apps/uiReact + Vite console. Private workspace; build core/static mein jaata hai, CI stale bundle par fail karta hai.
apps/demo-express, demo-nestjsSandbox servers jisse feature check hote hain.

Build order

core → express → fastify → nestjs → koa → hapi → hono → http → cli → ui (root npm run build).

Tests

Har package mein vitest. Core mein e2e, hardening, otel-compat aur persistence tests bhi hain.
